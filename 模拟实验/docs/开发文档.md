# 电路实验模拟器 · 开发文档（v1.0.0）

## 1. 架构

零依赖纯 ESM，无构建步骤。`node server.mjs` 起 5360 端口。

```
index.html
js/
  app.js          应用入口：视图切换、实验列表、右栏面板接线
  board.js        实验台编排：仿真调度、状态行、探针入口 __labBoard
  model.js        电路数据模型：元件/导线/网表/撤销栈/存档（v4）
  parts.js        元件外观 + 端子 + 参数面板描述
  symparts.js     原理图符号
  render.js       画布渲染 + pickAt（端子>元件>导线>孔位）
  interact.js     指针/键盘交互：放置、连线、旋转、右键删除、光标
  platforms.js    面包板 / 数字实验箱的孔位与器件
  solver.js       线性方程（高斯消元）+ 牛顿迭代
  devmodels.js    模拟元件模型（R/C/L/二极管/稳压管/BJT/运放/继电器/电位器…）
  simdc.js        直流工作点（MNA + 非线性 NR + 结果/报告）
  digmodels.js    数字逻辑模型（74LS00/02/04/08/32/86/74）
  simdig.js       数字稳态求值（三值逻辑 + 拓扑排序 + 环路检测）
  simtrans.js     暂态（梯形积分 + 事件驱动 TPD + 分帧运行器）
  simmix.js       混合信号边界（比较器/DAC/ADC/缓冲 + 跨域环路）
  waveview.js     波形查看器
  instruments-core.js / instruments.js   四件仪器（读数内核 / 面板）
  datastore.js / data-panel.js           数据系统（记录/CSV/JSON/存档迁移）
  examples-data.js / examples-measure.js / report.js  示例实验与报告
  experiment-config.js                   方案/故障注入/评分
  version.js      版本号单点
tools/
  check.mjs       静态语法检查（node --check 的替代，ESM 友好）
  test-model.mjs  模型/求解器自测（467 条）
  test-all.mjs    全量回归（静态 + 自测 + tools/probe/run*.mjs）
  bench.mjs       性能基准 B1–B5
  gen-examples.mjs 示例模板复算与生成
  probe/          各包验收探针（run5/6/7/8/…/13、probe14、runA/runB）
```

**数据流**：交互 → `model`（唯一数据源）→ `board.handleChange` → 防抖 300ms → `simulateNow`（DC+数字+混合）→ 面板/画布。暂态由波形面板/仪器显式触发。

**单一数据源原则**：读数、报告、模板、评分全部调用同一套 `solve*` 与 `examples-measure`，不允许 UI 层自己算一遍。

## 2. 仿真内核

| 内核 | 文件 | 说明 |
|---|---|---|
| 直流 | simdc.js | MNA 装配、接地可达性剪枝、短路检查、非线性牛顿（PN 结限幅 + 精修两段） |
| 数字 | simdig.js | 三值逻辑、拓扑排序、组合环检测、74 系列门/触发器 |
| 暂态 | simtrans.js | 电容梯形伴随（首步 BE）、电感梯形支路、时钟/脉冲绝对时刻、门 TPD 事件队列、分帧运行 |
| 混合 | simmix.js | VCC/2 阈值、DAC D/255·Vref、ADC round(V/Vref·255)、跨域瞬时依赖图环路检测 |

**数值口径**：电压 V、电流 A、电阻 Ω、电容 F、电感 H；存档只存用户参数与 type，模型常数不落盘。

## 3. 元件模型表

| type | 模型 | 关键参数 |
|---|---|---|
| resistor | 欧姆 | resistance (Ω) |
| capacitor | 直流开路 / 暂态梯形 | capacitance (F)、dielectric |
| inductor | 直流短路 / 暂态梯形支路 | inductance (H) |
| diode | 指数 Is/n | model: 1N4148 / 1N4007 |
| zener | 正向指数 + 反向雪崩 | vz |
| led | 指数（型号决定 n） | color、model: ideal/red/green/yellow/blue |
| transistor | Ebers-Moll | model: 2N2222 / 2N3906、beta |
| opamp | 有限增益 + 摆幅钳位 | model: LM741 / OP07 |
| relay | 线圈 100Ω + SPDT（30mA 吸合/20mA 释放） | — |
| pot | 两端电阻按滑臂分压 | resistance、wiper(%) |
| dip4 | 4 个独立开关 | s1..s4: on/off |
| buzzer | 有源 100Ω / 无源 1kΩ | mode |
| comparator/buffer74/dac8/adc8 | 混合边界（simmix） | threshold/hysteresis/vref |
| fgen | 正弦/方波/三角/直流 | wave/frequency/amplitude/offset/duty |

## 4. 存档 schema（v4）

```json

  "version": 4,
  "platform": "breadboard",
  "components": [{ "id": "r1", "type": "resistor", "x": 2, "y": 2, "rotation": 0, "params": {} }],
  "wires": [{ "id": "wire-1", "a": { "componentId": "r1", "terminal": "1" }, "b": { "componentId": "v1", "terminal": "+" } }],
  "stash": {},
  "instruments": { "tab": "dmm", "dmm": {}, "scope": {}, "la": {} },
  "records": []
}
```

迁移：`datastore.migrateArchive`（v1 数组导线 → 对象、补 stash/instruments/records；未来版本拒绝迁移）。
往返一致：`archivesEquivalent` 排除 time/savedAt/updatedAt 后逐字节比较。

## 7. 画布探针标记与数字结构缓存（2026-11-04）

### 7.1 画布可拖拽探针标记

- 模块：`js/probe-markers.js`（新增）；槽位契约在 `js/instruments.js` 导出的 `PROBE_SLOTS`。
- 四槽位 DMM / DMM B / CH1 / CH2，各自 `scope + key` 指向 instruments 状态字段。
  `setProbe(slot, netId)` 与下拉 `setDmm / setScope` 写**同一份状态**，`onProbeChange`
  回调让标记层同步，所以两个入口永远不会打架。
- 落点解析走 `board.pick(x, y)`：terminal → `netOf['c:…']`，node → `netOf['n:…']`，
  wire → 端点 `getNetOf`，component → 第一个端子。孤立端点 / 空白落点不挂点并给 toast。
- 标记位置存**网格坐标** `{ gx, gy }`（不是屏幕像素），写在
  `instruments.snapshot().markers` 里随 v4 存档走；`restore()` 自动回填，
  没有位置时会落到该网第一个元件端子上。未挂测点时停靠画布左上托盘。
- 视图跟随：`board.js` 的 `requestRender()` 每帧调 `board.onAfterRender(view)`；
  标记层 `onViewFrame()` 只在 `originX/originY/tileW/tileH/width/height` 变化时重投影，
  避免每帧写 DOM。注册 / 注销在 `app.js` 的 `wireInstruments()` / `destroyInstruments()`。
- 探针：`tools/probe/probe-markers.mjs`，由 `test-all.mjs` 按 `probe*.mjs` 自动发现。

### 7.2 B3 电路指纹结构缓存

- `js/simdig.js`：`circuitSignature()` 生成指纹（元件 id/type/params + 端子→网映射 +
  TTL 悬空策略 + 平台），命中则复用 `buildDigPlan()` 产出的
  `units / sources / drivers / order / unitByKey`，省掉收集与拓扑排序。
- **边界**：只缓存结构。每步仍清空 `levelIn / levelOut / edge / mode / invalid`、
  重算源电平、触发器记忆与混信边界输出；`resetDigState()` 同步清缓存。
  比较器 / ADC 的输出电平依赖本步模拟电压，特意留在 `solveDig()` 里重算，
  不进 `buildDigPlan()`（否则闭包会捕获旧的电压表，输出会被冻住）。
- `__labBoard.simdig.cache() / resetCache()` 供探针读命中数；`tools/test-model.mjs`
  有 7 条缓存回归（命中 / 参数失效 / 连线失效 / 时钟运行态不缓存）。
- 缓存改造时踩过的两个坑（已修）：组合 / 跨域环路早退分支要补回 `hasDigital`，
  否则面板误报"电路里没有数字元件"；混信求值上下文不能搬进结构构建函数。

## 8. HEP-DCTS-01 实物外观皮肤（2026-11-04）

### 8.1 约束：绝不新增第三个平台 id

`platforms.js` 只有 `breadboard` / `exp-box` 两个 id，且被以下位置硬依赖：
`model.loadCircuit()` 的非法值回退、存档 v4 的 `platform` 字段、`model.js` 的
`stash[platformId]` 暂存区、探针里大量 `exp-box:*` 节点 id、`getPlatform()` /
`isPlatformId()` / `platformIdOf()`。新增平台 id 会让旧存档与 900+ 项探针同时失效。

因此实物复刻走 **纯皮肤层**：`model.platform` 保持 `exp-box`，只替换平台层画法、
加 DOM 覆盖层、加仪器装饰层。平台几何、`platform.nodes`（含 `x, y`）与 `pickAt`
一律沿用原值，HEP 皮肤画孔位时也严格经 `project(view, x, y)` 投影，保证拾取 / 连线 /
存档不变。

### 8.2 新增的状态与缓存键

```js
// render.js
createView(canvas)          // 新增 skin: 'classic'
layerKey(view)              // 加入 view.skin，切换时重建离屏平台层
drawPlatform(...)           // view.skin === 'hep' && platform.id === 'exp-box'
                            //   → drawHepPlatform(ctx, view, platform, { project })

// board.js
const SKIN_KEY = 'lab-sim:skin';       // 独立于电路存档
readSkin() / writeSkin(id) / setSkin(id)
__labBoard.skin            // getter
__labBoard.setSkin(id)     // 写 localStorage + invalidatePlatformLayer + requestRender + onSkinChange
```

`skin` 只在 `view` 和 `board` 上，**不进 `model`、不进 `serializeCircuit()`**，
存档 schema 仍是 v4。探针 `probe-hep.mjs` 有专门断言：`savedData().hasSkin === false`。

### 8.3 文件与职责

| 文件 | 职责 |
|---|---|
| `js/hep-skin.js` | canvas 写实平台层。零 import（避免与 `render.js` 循环依赖），投影函数由 `api.project` 注入。导出 `HEP_SKIN_ID`、`HEP_MODULES`（6 模块定义）、`drawHepPlatform()` |
| `js/hep-panel.js` | 6 模块 DOM 覆盖层。导入 `HEP_MODULES` 与 `render.js` 的 `project`；只读 `__labBoard.model / simdig / simdc` 与 `instruments.read()` |
| `js/instruments.js` | `hepScopeFace()` / `hepFgenFace()` 两台真实仪器装饰层；`setSkin(on)` 触发 `renderBody()` |
| `js/app.js` | `#btn-skin` 接线、平台切换禁用、两个覆盖层合流 `onAfterRender`、销毁清理 |

**两个覆盖层共用一个帧回调**（`app.js`）：

```js
window.__labBoard.onAfterRender((view) => {
  if (probeMarkers) probeMarkers.onViewFrame(view);
  if (hepPanel) hepPanel.onViewFrame(view);
});
```

`onAfterRender(view)` 由 `board.requestRender()` 在 `renderScene()` 之后同步触发，
保证 DOM 覆盖层与 canvas 同一帧的视图变换对齐。两个覆盖层都只在 view 参数变化时
重投影，避免每帧写 style。

### 8.4 DOM 覆盖层的交互边界

```css
.hep-panel-layer { position: absolute; inset: 0; z-index: 4;
                   overflow: hidden; pointer-events: none; }
.hep-btn, .hep-bit { pointer-events: auto; }
```

只有按钮可交互，画布的拖拽连线 / 放置 / 右键删除 / 平移缩放完全不被抢走。
仪器装饰层同理：`aria-hidden="true"` + `pointer-events: none`，
`.inst-scope-canvas` 仍是原来那个 canvas 节点（只是外包了 `.hep-scope-bezel`），
`.inst-measure` 等既有选择器不变。

### 8.5 模块行为层只复用既有接口

`hep-panel.js` 不实现任何仿真逻辑：

- 拨位 → `__labBoard.simdig.toggleSwitch(id)`（内部走 `model.updateParams` + `handleChange`，
  于是自动触发防抖存档与重仿）。
- 单次脉冲 / 时钟步进 → `simdig.triggerPulse(id)` / `simdig.stepClock()`。
- 频率档位 → `model.updateParams(id, { frequency })` + `simdc.solve()`。
- 七段译码、逻辑笔 → 从 `model.getState()` 与 `instruments.read()` 实时推导，
  `stateKey()` 做脏检查，避免每帧重建 DOM。

### 8.6 探针与踩坑

`tools/probe/probe-hep.mjs`（39 项）用 `process.env.__LAB_PROBE_LIB = '1'` 复用
`runB.mjs` 的 `ensureServer / bootEdge / evalJs / sleep / waitFor`，输出统一的
`=== 探针结果：N/M 通过 ===`，因此被 `tools/test-all.mjs` 自动发现并汇总。

平台层「真的画成蓝色」用像素断言：取 5 个网格点 `project()` → `getImageData(3×3)`
求均值，要求 `b - r > 30`；切回 classic 后要求 `b - r` 至少降 20。

**坑：探针读存档要等防抖**。`scheduleSave()` 是 500ms 防抖，平台切换会重置计时器。
首轮探针在切换后只 `sleep(220)` 就读 `lab-sim-circuit-*` 得到 `null`，误报失败。
修法不是改产品，而是探针里加 `waitSavedPlatform()` 轮询（4s 上限，超时返回 null
不抛异常），并限定优先读当前 `expId` 对应的键，避免命中历史残留键。

### 8.7 发布注意

`dist/` 必须重新执行 `node tools/build.mjs`；游戏大厅同步用 `cp`（Git Bash 无
`rsync`），见第 6 节。`hep-skin.js` / `hep-panel.js` 是新增文件，同步时别漏。
WorkBuddy 托管入口会覆盖已上线链接，需用户当轮明确授权才重新发布。

## 9. 显示分层 / 帧前钩子（2026-11-04 增补②）

### 9.1 需求

首轮 6 张 DOM 模块卡片默认常驻遮住蓝色主板。用户要求「鼠标移到元件上或点击元件才会
显示名称等信息」，并一次性确认四项选择全部落地：悬停出信息 + 点击展开、丝印可开关、
全隐藏 + 热点 + 总开关、状态灯入画布 / 图钉 / 小屏抽屉 / 教学模式。

### 9.2 三层显示与状态归属

| 层 | 载体 | 状态 |
|---|---|---|
| 静态丝印 | canvas 平台层 `stamp()` | `view.hep.silk` → 模块级 `SILK_ON`；品牌铭牌 `force` 常驻 |
| 动态信息 | 单例 `.hep-hover-card` | `hoverId / hoverHit / hoverPinned`，`pointer-events:none` |
| 操作面板 | 6 张 `.hep-module-card`（默认 `hidden`） | `openId`（一次一张）、`pinned:Set`、`view.hep.all / teach` |

偏好只写 `localStorage`：

```js
const HEP_VIEW_KEY = 'lab-sim:hep-view';
const HEP_VIEW_DEFAULT = { silk: true, teach: false, all: false };
```

`model`、`serializeCircuit()`、存档 v4 一律不碰。`isShown()` 的判定顺序：
`teach || all || pinned.has(id) || openId === id`。

### 9.3 帧前钩子 `onBeforeRender(view)`（关键）

平台层是离屏缓存，`ensurePlatformLayer()` 用 `layerKey(view)` 判断要不要重建。
若状态灯数据在 `renderScene()` 之后才写，缓存键已经算完，改动要等下一帧才生效。
因此 `board.js` 在 `renderScene()` **之前**调用帧前钩子：

```js
const start = performance.now();
if (board.onBeforeRender) board.onBeforeRender(board.view);
renderScene(board.view, board.scene);
if (board.onAfterRender) board.onAfterRender(board.view);
```

`hep-panel.writeRuntime(view)` 计算 `{ bits, digit, freq, probe }`，拼出
`view.hep.runtimeKey`（含 bits / digit / freq / probe / hoverId / silk / teach / all），
变化即 `invalidatePlatformLayer()`。`layerKey()` 相应把 HEP 状态纳入：

```js
const hepKey = view.skin === HEP_SKIN_ID
  ? `${h.silk ? 1 : 0}${h.teach ? 1 : 0}${h.all ? 1 : 0}|${h.hoverModule || '-'}|${h.runtimeKey || ''}`
  : '-';
```

职责边界：`onBeforeRender` 只写 canvas 状态，`onAfterRender` 只对齐 DOM 覆盖层
（probe-markers 的 `onViewFrame` 与 hep-panel 的 `onViewFrame` 共用同一回调）。

### 9.4 DOM 事件边界（改这块前必读）

- `.hep-panel-layer` / `.hep-hover-card` 恒 `pointer-events: none`；只有
  `.hep-btn / .hep-bit / .hep-pin` 为 `auto`。
- 监听挂在 `host` 的 **bubble** 阶段，从不 `preventDefault`、不阻止冒泡；
  仅卡片内按钮自己 `stopPropagation()`，避免重复触发展开。
- 放置元件幽灵态（`board.scene.ghost`）或连续放置模式下直接 `return`，让画布交互优先。
- 点到真实元件（`board.pick()` 命中）只切换 `hoverPinned`，不展开操作面板。
- 空白分支必须同时清 `hoverId / hoverHit / hoverPinned`，否则注入式点击 / 触摸
  （没有配套 `pointermove`）会留下悬停卡。

### 9.5 小屏抽屉

`window.innerWidth <= 720` 时 CSS 把 `.hep-panel-layer` 改成
`display:flex; flex-direction:column; justify-content:flex-end`，卡片
`position: relative`；`onViewFrame()` 在该模式下不再写 `left/top`，改由 flex 底部堆叠。

### 9.6 探针与两处踩坑

`tools/probe/probe-hep.mjs` 由 39 项扩到 **86 项**，纳入自动发现后全量
**1023/1023**。两个值得记住的坑：

1. **像素断言别用单点**。首版 `pixelAt(6.4, 0.88)` 落在中文字形缝隙且被后续绘制

   也补上，让触摸路径一并受益。

## 10. 数字芯片扩展 / 16 脚封装 / 12 个课程实验 / 手感观感（指令包 16–18）

### 10.1 为什么多了 `digprims.js`（ESM 循环依赖的坑）

`digital-chips.js` 需要 `X / TTL / TPD_* / norm / logicNot`。如果它直接
`import './digmodels.js'`，而 `digmodels.js` 又要 import 它，就形成循环：
求值顺序上芯片模块先跑，此时 `digmodels.js` 里的 `const TPD_GATE` 还在 TDZ，
`buildLs138()` 一读就 `ReferenceError`。

解法是把三值逻辑原语下沉成零依赖 leaf 模块：

```
digmodels → digital-chips → digprims      （单向，无循环）
```

`digmodels.js` 仍然 `export { X, TTL, norm, ... }`（re-export），所以既有
`import { norm } from './digmodels.js'` 的代码一行都不用改。

### 10.2 8 颗 MSI 芯片（任务 A）

`js/digital-chips.js` 导出 `NEW_DIG_MODELS / NEW_PIN_LABELS / NEW_LEGACY_TYPES /
NEW_ORDER`，`digmodels.js` 在 `DIG_MODELS` / `DIG_MODEL_ORDER` 之后合并，
**必须早于 `DIGITAL_TYPES` 求值**，否则元件库与覆盖断言会漏型号。

| 型号 | 封装 | 关键行为 |
|---|---|---|
| 74LS138 | DIP-16 | G1=1 且 G2A=G2B=0 才使能，按 CBA 选通唯一低有效输出 |
| 74LS148 | DIP-16 | 输入/输出低有效，IN7 优先级最高，编码 = 7 − 索引 |
| 74LS151 | DIP-16 | G 低有效，Y/W 互补，地址为 X 时输出 X |
| 74LS283 | DIP-16 | 逐位全加，C0 进位输入，C4 进位输出 |
| 74LS85 | DIP-16 | 从 A3/B3 串行比较，全等时输出 = 级联输入 |
| 74LS112 | DIP-16 | 双 JK，**下降沿**触发，PR/CLR 异步优先，双低为不稳定态 |
| 74LS160 | DIP-16 | 十进制同步计数器，CLR/LOAD 同步，RCO = ENT ∧ count=9 |
| 74LS194 | DIP-16 | 异步清零，S1S0 = 00 保持 / 01 右移 / 10 左移 / 11 置数 |

时序芯片统一 `unit.kind === 'ff'`，`unit.fn(values, prevState)` 返回
`{ outputs, state, edge, mode }`；`state` 按 `unit.id` 分开存。
旧存档短号走 `NEW_LEGACY_TYPES`（74138 → 74LS138 等）。

### 10.3 DIP-16 封装（任务 B）

`parts.js` 的 `ic74xx16`：1..8 顶边、9..16 底边、8=GND / 16=VCC、`size 8×3`。
型号下拉用**单一来源**过滤——数字模型的 `power.vcc`：

```js
function modelOptionsByPins(pinCount) {
  return DIG_MODEL_ORDER
    .filter((id) => Number(DIG_MODELS[id].power.vcc) === pinCount)
    .map((id) => ({ value: id, label: DIG_MODELS[id].label }));
}
```

`drawIc` 不再写死 `PARTS.ic74xx`：端子几何读 `PARTS[comp.type]`，电源脚高亮读
`getDigModel(...).power`，所以 14/16 脚共用一套画法。原理图侧新增
`buildIc16Pins()`，`drawIc` 的盒体高度改为 `sym.size.h - 0.6`（14 脚 → 7.4，
16 脚 → 8.4），不再写死。

### 10.4 数字测量泛化（任务 D）

`examples-measure.js` 的 `digital` 分支现在支持：

```js
measure: {
  type: 'digital',
  unit: 'u1',
  inputs: ['sc', 'sb', 'sa'],     // 扫描的开关，inputs[0] 是最高位（行标签顺序）
  outputs: ['15', '14', '13'],    // 输出引脚向量，按序拼成 0/1/X 字符串
}
```

三点必须注意：

1. **必须走 `solveCoupled`**，不能只调 `solveDig`。使能脚常直接接 +5V/GND
   （模拟域电压源），纯数字求解读不到这些电平；`solveCoupled` 内部的
   `analogView` 会排除数字源，既让直流收敛又能把节点电压喂给数字求解器。
2. 扫描会真的改开关状态，跑完要**恢复原态**，否则报告截图与真值表对不上。
3. 未驱动 / 不确定一律写 `X`，不装作 0 或 1。
4. 老结构（只有 `pins: [inA, inB, out]`）继续走"前两个逻辑开关"的回落路径，
   01/08 两个实验行为不变。

### 10.5 12 个课程实验与 7 个方案（任务 C）

`examples-data.js` 追加 `dig-01..dig-12`；`experiment-config.js` 追加
`D1/D3/D6/D9/D10/D11/D12`。**所有 target 都由复算得出**，不是手写：

- 组合实验（01–08、12）用 `digital` 真值表，target 是
  `000→0,001→1,...` 形式的完整字符串；
- 时序实验（09/10/11）用 `transient + digital:true` 测频率。

两个必须记住的实测结论：

- **74LS160 是十进制**，QD 每 10 个时钟循环一次 → **100Hz**（不是 62.5Hz）。
- **74LS194 环形的初始态是全 0**，DSR 直接接 Q3 永远不会动；必须经反相器
  （Q̄3 回灌 DSR）才是 8 分频的 Johnson 计数器 → **125Hz**。

另外 **SR 锁存器不能用静态数字测量**：交叉耦合是组合环路，`solveDig` 会整体
返回 `ok:false`（`检测到组合逻辑环路`），于是所有 compStates 都没有。D08 因此
改成「74LS00 门控时钟 + 74LS74 异步置位/清零」，并在步骤里把这个限制讲清楚。

### 10.6 手感与观感（任务 E）

**电平着色**（`render.js` + `board.js`）：仿真后 `board.sim.dig.netLevels`
按 net 映射到每条导线，存进 `scene.levelView.byWire`：

```js
levelView: { on: readLevelColor(), byWire: new Map() }  // level ∈ 1 / 0 / 'X' / 'F'
```

高=绿 `#5fd39a`、低=蓝灰 `#6f83a8`、X=琥珀虚线、未驱动（F）=半透明灰。
悬停某条导线时其余 net 压暗到 30%。偏好存 `lab-sim:level-color`，工具栏
「电平」按钮切换。

**流动点**：只在 `simtrans.start()` 到 `onDone/onError/stop` 之间开一个 rAF
循环推进 `scene.flow.phase`，停止即关；`prefers-reduced-motion` 直接不开。

**示波器拟真**：8 行 × 10 列分度，每大格再分 5 小格；**尺寸不变就不重设
`canvas.width`**（重设会清空像素），每帧只铺 6% 底色形成荧光余辉；轨迹带
同色微光；在 CH1 上找第一个上升沿画虚线触发光标 + 左侧触发电平箭头。

**落点预览**：拖动时 `scene.ghost` 合法绿 / 非法红，吸附结果直接复用
`SNAP_RADIUS = 2` 的命中计算。

**命中尺寸与仲裁**：端子半径 `max(12px, tileW*0.5)`；元件本体命中区放大 1.15×。
两者会打架——小元件（电阻 3×1）的两个引脚足以把整个本体罩住——所以加了一条
仲裁规则：**指针在元件本体内部且距最近引脚 > `max(6, tileW*0.22)` 时，本体赢**。
这样"点引脚连线"和"抓元件拖动"都还成立。

**动效令牌**：`--dur-fast/med/slow` + `--ease-out`，只动 `transform/opacity`；
`prefers-reduced-motion` 下统一关掉过渡与动画。
