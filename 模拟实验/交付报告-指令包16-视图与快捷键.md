## 3. 四项必答

### ① 连续缩放：锚点公式 / 与档位共存 / 触控板区分 / 双指阈值

**锚点公式**——不推解析解，用「取点 → 改 zoom → 量偏移 → 反补 pan」：

```js
export function setZoomAt(view, z, sx, sy) {
  const gp = unproject(view, sx, sy);       // 光标下的网格点
  view.zoom = clamp(z);
  applyZoomPan(view);                        // 先按中心锚重算 origin
  const p = project(view, gp.gx, gp.gy);     // 同一个网格点的新屏幕位置
  view.panX += sx - p.x;                     // 把差补进 pan
  view.panY += sy - p.y;
  applyZoomPan(view);
}
```

这样做的好处：**对 iso / flat / 任意旋转角都成立**，不必为三种投影各写一套锚点公式。
实测漂移 `0.00px`（远小于 2px 要求）。

**与 `ZOOM_LEVELS` 共存**：
- `ZOOM_LEVELS = [1, 1.5, 2, 3]` 只服务「跳档」（`2`/`3` 键、工具栏按钮、`zoomIn/zoomOut`）；
- 连续区间另设 `ZOOM_MIN = 0.5 / ZOOM_MAX = 4`，滚轮与双指写连续值；
- 两者共用同一个 `view.zoom`，所以工具栏读数、`2`/`3` 键、滚轮三者天然同步；
- `zoomOut` 在 1× 再降会落到 0.5×（连续区间下限），`0` 恒回 1×。

**触控板捏合 vs 普通滚轮**：都走 `wheel`。`event.ctrlKey === true` 是浏览器对触控板捏合的
约定标记，用更大的系数（`k=0.01` vs `0.0022`），否则捏合会慢得像没反应。
**普通双指滑动（无 ctrlKey）仍然缩放**——这是取舍：桌面浏览器无法可靠区分「鼠标滚轮」与
「触控板双指滑动」，而用户明确要求「鼠标滚轮缩放」，所以统一按缩放处理（已写进代码注释）。

**双指阈值**：
- 缩放：两指距离比偏离 1 超过 **1.5%** 才动 zoom（防手指抖动把画面缩没）；
  一旦缩放过一次就持续跟随，避免两指先后移动造成「停在错误倍率」；
- 平移：中点位移超过 **0.5px** 才写 pan；
- 旋转：两指夹角变化超过 **8°（0.14 rad）** 才进入旋转，且**旋转优先**——进入旋转后本帧不再
  缩放，避免「又缩又转」的糊手感；松手吸附到**最近 90°**。

### ② 水平正视：两种投影的公式、切换时机、旧代码的等距假设、回归证据

```js
// iso
lx = (gx - gy) * tileW / 2;   ly = (gx + gy) * tileH / 2;
// flat
lx = gx * tileW;              ly = gy * tileH;          // tileW === tileH === cell
// 两者之后再绕画布中心做整页旋转（仅 flat）
x = cx + dx*cos - dy*sin;     y = cy + dx*sin + dy*cos;
```
`unproject` 是严格逆运算：先逆旋转，再按对应投影反解。

**切换时机**：`setProjection()` 只改 `view.projection`，随后 `relayout()` 重算 fit 基准
（flat 的 fit 用 `availW/cols`、`availH/rows`，旋转 90/270 时按交换后的长宽比适配），
再 `invalidatePlatformLayer()` + `requestRender()`。**zoom / pan 不动**，所以从 iso 切到
flat 再切回来，画面回到原来的倍率与位置。

**原来写死等距假设的地方**（grep `tileW / 2` / `(gx - gy)`）：
1. `project/unproject` —— 唯一真源，改成投影分派；
2. `layoutView` 的 fit 计算 —— 加 flat 分支；
3. `componentFrame.project` —— 原先是 `dx*tileW, dy*tileH` 的屏幕正矩形，改为
   `project(comp + 局部偏移) - project(comp)`；
4. `drawPlatform` 的 `platePrism` —— 走的还是 `project`，无需改；
5. `renderScene` 贴平台层的 `drawImage` 目标矩形 —— 保持「以中心缩放 + pan」不变，
   因为旋转被烘进 `project`，缩放与旋转都绕画布中心，可交换。

**回归证据**：Z3 断言 flat 下 `+x` 增量 `(18.78, 0)`、`+y` 增量 `(0, 18.78)`（正方形孔阵）；
点端子命中的是同一个端子；切回 iso 后 `+x/+y` 增量与切换前逐位相等。
拖拽吸附 / 连线端点 / 放大镜 / 探针标记全部走同一个 `project`，`run5–run13`、`runA/runB`、
`probe-markers`、`probe-hep` 全绿即为回归证据。

### ④ 悬停矩阵：状态源、即时隐藏、替代查看路径

**状态源**（都在 board 层，hep-panel 只读）：
- `board.scene.selection` —— 是否选中；
- `board.interact.isBusy()` —— 拖拽中 / 平移中 / 连线中 / 待放置 / 连续放置 / 导线工具 / 落点幽灵，
  这七种任一为真即 `busy`。

判定：`canHover() = !selection && !isBusy`；显示还要求 `hoverId || hoverHit` 非空。

**即时隐藏**：`refresh()` 每帧（`onAfterRender`）先跑一次 `if (!canHover()) 清空 hover`，
所以「点中元件 → 选中 → 同一帧内信息卡消失」，不需要等指针移动。
`onPointerMove()` 进门先判 `canHover()`，不满足直接 `clearHover()`。

**去掉钉住后的替代路径**：
1. **图钉按钮**（模块卡片上的「钉」）——常驻的是**模块面板卡片**，不是悬停信息卡；
2. 点模块 → 展开单张操作面板（正文里参数、按钮、读数都在）；
3. 「模块面板」总开关 / 教学模式 —— 6 张卡片名一起摆出来当索引；
4. 右侧属性面板 —— 选中元件后参数、位置、类型全部可查可改。

## 4. 设计取舍

1. **投影只有一处真源**。所有绘制与拾取都走 `project/unproject`，包括元件本体。
   代价是 `componentFrame` 从「屏幕正矩形」改成「投影增量」，所有元件的观感都变了
   （电阻、LED 在 iso 下从水平矩形变成斜平行四边形）——这正是第 ③ 条的根因修复。
2. **删除 `applyComponentRotation`**。原来用 canvas 旋转 90°，在等距投影下
   `S·A ≠ A·R`（屏幕旋转 ≠ 网格旋转），本身就是错的。改为把 rotation 折进局部→网格映射
   （公式与 `terminalPos` 逐字一致），两种投影下都严格正确。
3. **flat 下所有棱柱高度归零**（`setFlatShading`）。`lift()` 在 flat 模式返回原点，
   `prism()` 的侧面自动退化为零面积多边形，只剩顶面 —— 不改任何 part 的绘制代码就得到
   「无斜边厚度」的正视图，也保证芯片本体与插座内腔严格同矩形。
4. **整页旋转只对 flat 开放**。iso 下转 45° 会让孔位辨认变难（且拾取链路全要回归），
   收益极低；`setRotate` 在 iso 下直接返回 0，切回 iso 时自动归零。
5. **`Shift` 一律吞掉**。规格要求「不得依赖 Shift」，与其逐条判断，不如在
   `handleKeyDown` 顶部 `if (event.shiftKey) return;` —— 从根上保证「Shift + 任意键」无功能。
6. **`__labBoard.view` 保持原样**。本包新增的是 `view.projection / view.rotate / view.gridOn`
   三个**字段**（探针直接读），外加独立的 `__labBoard.camera` 控制面；
   没有把 `view` 换成 getter 对象，避免打断既有探针（`b.view.dpr` 等 7 处）。
7. **模式面板收起态只显示名称**。教学模式把 6 个名字当索引，点开才渲染正文——
   比「6 张全展开」更符合「不要霸占屏幕」的原始诉求。

## 7. 已知限制

1. **触控板普通双指滑动也会缩放**。浏览器无法区分它与鼠标滚轮；要「双指滑动 = 平移」只能
   加显式开关（未做，避免多一个要记的按钮）。
2. **iso 模式不支持整页旋转**（按规格只对 flat 开放）。iso 下按「旋转」会提示切到水平正视。
3. **flat 下 `lift()` 归零**是全局开关，实物外观（HEP 皮肤）自带的浮雕仍按自己的 `lift` 绘制，
   所以 HEP + flat 会保留一点面板浮起感——不影响拾取与几何。
4. **双指手势没有做惯性**。松手即停，避免与「松手吸附 90°」的旋转收尾打架。
5. `zoomOut` 在 1× 会降到 0.5×（连续区间下限）。这是有意为之：既然支持 0.5×–4×，
   键盘缩到底不该卡在 1×。
