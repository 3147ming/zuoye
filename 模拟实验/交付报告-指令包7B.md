## 3. 四项必答

### ① 四向旋转：状态存储、换算、180°/270° 规则、旧存档影响、四向实测

**状态存储**：`comp.rotation ∈ {0, 90, 180, 270}`（整数角度）。`model.rotateComponent(id)` 每次 `next = (comp.rotation + 90) % 360`，越界/重叠校验通过后 `pushUndo` 再赋值。`serializeCircuit()` 原样写入 `rotation` 字段。

**四套换算**（彼此独立、各自自洽，端子屏幕坐标已交叉验证重合）：

| 变换面 | 函数 | 旋转中心 | 公式 |
|---|---|---|---|
| 占位（宽高） | `parts.footprintOf(def, r)` | — | 90/270 交换 w↔h；0/180 不变 |
| 端子（面包板） | `parts.terminalPos` | 整数网格矩形左上角 `[0..w-1]×[0..h-1]` | 90→`(h-1-dy, dx)`；270→`(dy, w-1-dx)`；180→`(w-1-dx, h-1-dy)` |
| 面包板绘制 | `render.applyComponentRotation` | 同左上角 | 90→`translate((h-1)·cell,0)+rotate(π/2)`；180→`translate((w-1)·cell,(h-1)·cell)+rotate(π)`；270→`translate(0,(w-1)·cell)+rotate(-π/2)` |
| 原理图符号 | `symparts.pinPos/symSize/drawSymbol` | 符号中心 | 90→`(h-dy, dx)`；270→`(dy, w-dx)`；180→`(w-dx, h-dy)`；引脚 `side` 经 `rotateSide` 按 90° 步进 left→top→right→bottom |

面包板与原理图是两套独立变换（一个绕左上角、一个绕中心），但端子屏幕坐标在 0/90/180/270 四档下均重合，视觉一致。

**180° 与 270° 占位宽高交换规则**：**180° 不交换**（3×1 → 3×1），**270° 交换**（3×1 → 1×3）。越界/重叠校验一律按旋转后实际占位计算。

**旧存档（只有 0/90）影响：无。** `loadCircuit` 逐条尽力恢复，`rotation` 取值 0/90/180/270 均为合法值，原样载入、不做静默改写。实测：仅含 `rotation:90` 的旧档载入后 `rotation` 仍为 90，`skippedComponents=0`。

**四向实测数据**（resistor 3×1 @ 网格 (2,2)，探针 2.3 逐档断言）：

| rotation | 占位 (w×h) | 端子 1 网格 | 端子 2 网格 | serialize 往返 |
|---|---|---|---|---|
| 0° | 3×1 | (2,2) | (4,2) | — |
| 90° | 1×3 | (2,2) | (2,4) | 旧档载入保持 90 |
| 180° | 3×1 | (4,2) | (2,2) | serialize→load 保持 180 |
| 270° | 1×3 | (2,4) | (2,2) | serialize→load 保持 270 |
| →0° | 3×1 | (2,2) | (4,2) | 连按 3 次到 270°，第 4 次回 0° |

补充：正方占位（w===h）元件拒绝旋转（`该元件为正方占位，旋转无变化`）——正方形 footprint 旋转无几何变化；当前元件库无正方元件，实测不触发。

### ② 重做：栈结构、清空时机、与既有撤销行为的一致性

**数据结构**：`undoStack` / `redoStack` 均为快照数组，元素为
`{ label, components: cloneComponents(state.components), wires: cloneWires(state.wires) }`。
clone 是深拷贝（`params` 展开、`terminals` 逐项展开），保证快照与活状态零共享。两栈上限 `UNDO_LIMIT = 60`，超出 `shift()` 丢最旧。

**清空/压栈时机**：
- `pushUndo(label)`：任何结构变更**之前**调用，压当前快照入 `undoStack`，并 `redoStack = []`（标准"新操作作废重做"）。
- `undo()`：`undoStack.pop()` → 把**当前态**压入 `redoStack` → 恢复快照。
- `redo()`：`redoStack.pop()` → 把**当前态**压回 `undoStack`（超上限 shift）→ 恢复快照。因此 redo 后仍能再 undo，两栈互为镜像可无限往返。
- `clearUndo()`（进入新实验、平台切换）：两栈同清。

**与既有撤销行为完全一致**：`interact.undo()` 与 `interact.redo()` 走同一收尾路径——
1. 清空 `scene.selection` 与 `scene.wiring`（快照恢复后选中项/起点可能已不存在）；
2. `onSelectionChange()` → 属性面板重建 + 原理图高亮同步；
3. `onChange('undo'|'redo')` → `handleChange` → 体检（悬空导线）→ 落盘 → 属性面板 → 重绘 → `notifyModelChange` 事件桥 → `scheduleSimulation`（300ms 防抖重仿）；
4. toast "已撤销/已重做" 或 "没有可撤销/可重做的操作"。
快捷键 Ctrl+Y / Shift+Ctrl+Z 与 Ctrl+Z 同一 `handleKeyDown` 监听、同一"输入控件聚焦不吃快捷键"规则（`isTypingTarget`）。

### ③ 右键删除：完整交互矩阵与"不误删"保证

**矩阵**（`handleContextMenu`，仅画布内 `preventDefault`）：

| 当前状态 \ 右键目标 | 导线 | 元件 | 端子 | 空白 | 画布外（工具栏/面板） |
|---|---|---|---|---|---|
| 普通（无选中） | 删该导线 | 删元件 + 连带导线（含闪烁预告） | 删**所属元件** | 清空选中，不弹 toast | 浏览器默认菜单 |
| 已选中元件/导线 | 删该导线 | 删元件 + 连带导线 | 删所属元件 | 清空选中 | 默认菜单 |
| **连线起点态** | 只取消连线 | 只取消连线 | 只取消连线 | 只取消连线 | 默认菜单 |
| 放置模式（pendingType） | 同普通 | 同普通 | 同普通 | 清空选中 | 默认菜单 |
| 放大镜开启 | 同普通（右键不进放大镜分支） | 同普通 | 同普通 | 清空选中 | 默认菜单 |

与 Delete 键并存：两者删除语义一致（同一 `model.removeComponent/removeWire`、同一连带导线提示、同一闪烁预告）；差别仅在 Delete 需先选中、右键免选中。

**如何保证不误删**：
1. **作用域隔离**：`contextmenu` 处理器第一件事是判定指针是否在画布矩形内，不在则直接 return，绝不 `preventDefault`——工具栏/右栏/元件库右键完全保持浏览器默认行为。
2. **连线起点态优先级最高**：`if (scene.wiring) { cancelWiring(); return; }` 在任何删除分支之前，起点端子所属元件不可能被误删（7A 智能聚焦连线共存）。
3. **空白右键零副作用**：只清选中/取消连线，不删任何对象、不弹 toast。
4. **端子按"所属元件"处理**，不出现"删掉半个元件/只剩端子"的中间态。
5. **全部走 model API + 撤销栈**：`removeComponent`/`removeWire` 在变更前 `pushUndo`，Ctrl+Z 可完整恢复（含连带导线，探针 2.6/2.7 实测）。
6. 删除对象类型显式判定（`hit.type`）：只处理 `wire` / `component` / `terminal`，其余命中一律当作空白。

### ④ 反馈项：toast 队列、删除预告、计算中指示

**toast 队列（2.10）**：单条顺序展示 + 队列上限 3（超出丢最旧）。
- 机制：`showToast` 入队（`length>=3` 时 `shift()` 丢最旧），`pumpToast` 取队首渲染，驻留 1600ms + 退场 240ms 后抽下一条；同屏**恒为 0 或 1 条**（并有 `children.length>1` 兜底清理）。
- 连续放置的高频提示在**交互层合并**为"已放置 N 个 xxx"（`state.placeCount` 累计，退出模式归零），所以顺序队列不会被刷屏。
- **取舍**：2.10 允许"挤掉旧的"或"顺序展示"二选一，选**顺序展示**——文本合并会丢信息（连续删除看不出删了哪条导线）；上限 3 是防极端高频下积压过久（最新提示最迟约 5.5s 内出现）。

**删除预告（2.6）**：删除瞬间连带导线以琥珀色 `rgba(242,169,59,0.95)` 重描约 150ms。
- 实现：`interact.flashWires(list)` 设 `scene.pendingFlash = { wires, until: performance.now()+150 }` 并请求重绘；`render.drawFlashWires` 在 `renderScene` 末尾按有效期重描一次；170ms 后清字段再重绘。复用既有 `requestRender`，**不新增动画循环**。
- **取舍**：2.6 推荐"删除瞬间连带导线闪烁一次"而非"删除前高亮 350ms + 确认"——不增加确认步骤、保持"直接删"的手感，又让用户看清删了什么。

**计算中指示（2.11）**：状态源是 `board.scene.simPending`（布尔）。
- `scheduleSimulation()`（300ms 防抖）进入即 `scene.simPending = true` 并 `renderSimPending()` 把状态行写成"计算中…"；
- `simulateNow()` 求解完成 `scene.simPending = false` 并 `refreshHealth()` 恢复"元件 N · 导线 N · 网络 N"；
- 状态行即 `#canvas-status`（既有 `refreshHealth` 的输出位），app 层无需额外订阅。
- **取舍**：只覆盖防抖等待期（300ms 内用户可感知）；求解本身极快（model 自测 96 门单次 <6ms），不值得再做 running 态；不改防抖与求解逻辑本身。

## 4. 设计取舍

1. **拖拽连线与点A点B共用 `finishWire`**：同一校验、同一撤销栈，杜绝两套语义漂移；位移阈值 4px（`DRAG_THRESHOLD`，注释已写）区分"点击进起点态"与"拖拽释放"。
2. **元件光标选 `move`**（2.8 允许 move/pointer 二选一）：元件可拖动，`move` 语义更直观；导线用 `pointer`（可选中/可右键删）。
3. **四向旋转对正方占位拒绝**：转了也是原地踏步，如实报错比静默不动更可预期。
4. **淡入用纯 CSS transition + rAF 移除 class**（2.9 明示不加 JS 动画循环）：加 `is-fading`（opacity:0）→ 强制回流 → 下一帧移除，过渡真实从 0 起跑。
5. **连续放置的 Esc 退出整个模式**（含按钮态复位），而非只退出待放置类型——与 2.4"Esc 或再次点击按钮退出"字面一致；按钮态经 `placestate` 事件同步。
6. **`__labBoard` 额外暴露 `geometry`**（端子网格/屏幕坐标）：2.12 允许"若结构不同以实际为准"，拖拽连线/光标/右键删除探针需要真实坐标才能构造可复现的命中。

## 5. 自检发现并修复的问题（4 个，均由探针暴露）

1. **【功能性】`pickAt` 孔位优先于导线 → 实验箱上导线几乎点不中**。
   实测对导线邻域 3325 点采样，**仅 3 点**能命中导线（孔位命中半径 8.8px > 导线 6px，且实验箱孔位密集，导线整条被孔位阴影覆盖）。后果：右键删导线、悬停导线光标、导线选中在实验箱上全部失效。
   **修复**：把导线命中提到孔位之前（导线本就绘制在台面孔位之上），优先级改为 端子 > 元件本体 > **导线** > 孔位。修复后 2.7 右键删导线、2.8 导线 `pointer` 全绿。
2. **【隐患】`scene.circuit` 存死引用**：`model.loadCircuit`/`createCircuit` 会整体替换 `state` 对象，死引用导致 `pickAt`/渲染看到旧电路（元件点不中、导线看不见）。生产路径目前只在 init 时 load 故未触发，但属同型隐患。
   **修复**：改为活引用 getter `get circuit() { return model.getState(); }`。
3. **【功能性】Esc 只清 `pendingType` 不退连续放置模式**：模式残留后，所有画布点击都变成"放置"而不是"连线/选中"（直接拖垮 2.1/2.2/2.8 三组探针）。
   **修复**：Esc 走 `setContinuousPlace(false)` 并派发 `placestate` 事件同步工具栏按钮态。
4. **【UI 同步】`viewzoom`/`lensstate` 事件未 `bubbles`**：canvas 上派发的 CustomEvent 到不了 window 上的订阅者，键盘 +/-/0 的倍率读数与 M 的放大镜按钮态不同步；顺带发现"点击关闭放大镜"不派发 `lensstate`。
   **修复**：三处事件补 `bubbles: true`，点击关镜补派发。
