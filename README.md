# 基于Web的2D横版世界大厅游戏合集设计与实现

一个纯前端的单页游戏合集入口：**19 屏世界**——中间一条可走的走道
`工具总门 ← 中心广场 → 游戏总门`，两端的总门用浮层选单把玩家**传送**到 21 个内容区块
（3 个工具 + 18 个游戏，其中 6 个「脑力街机」是线上直达、1 个「仓库行动」是跨域 FPS 直达、
5 个「联机对战」共用一套房间服务）。每个区块都有自己的一位 NPC，负责讲清「这是什么 / 怎么玩 / 怎么回去」。

这一版新增**联机对战**：房主建房拿一个 5 位数字房号，朋友输号就能进来一起玩——见 3.24 节。

本项目为课程大作业，**完全独立**，与任何既有项目无关。

线上地址（Cloudflare Pages，Git 集成自动部署）：<https://zuoye-e0c.pages.dev/>

## 一、运行方式

直接双击 `index.html` 即可（`file://` 协议下可用，全部脚本都是传统 `<script>`，没有 ES Module 的跨域限制）。

如需本地静态服务器（可选）：

```bash
cd D:\Projects\WorldHub
python -m http.server 5350
# 浏览器打开 http://127.0.0.1:5350/
```

### 要联机

**线上版（1.27.0 起）直接就能联**：打开 `https://zuoye-e0c.pages.dev` → 联机大厅 → 建房拿房号（1.28.0 起多了「招式格斗」），
朋友输号进房。房间服务跑在 Cloudflare Worker（`wss://worldhub-ws.3147456217.workers.dev/ws`），
玩家**不需要**装 Node、不需要起隧道、不需要填地址。

下面这段是**本地开发/离线内网**时才需要 —— 单机内容在 `file://` 下就能玩，
只有想在本地起一套房间服务时才用：

**最省事：把 `开服.mjs` 放到任意一个文件夹，`node 开服.mjs`。**
它是一个零依赖单文件，不需要 `tools/`、不需要 `npm install`、不需要在项目目录里：

```powershell
node 开服.mjs              # 起服务 + 公网隧道，打印可分享地址
node 开服.mjs --local      # 只起服务，同一个 WiFi 玩
node 开服.mjs --port 9000  # 换端口
```

在项目目录里也可以直接双击 `开服.bat`，或跑完整版脚本（两者等价，完整版还能顺带托管静态页面）：

```powershell
cd D:\Projects\WorldHub
node tools/tunnel.mjs         # 起服务 + 公网隧道 + 静态预览
node server/index.js          # 只起房间服务，默认 0.0.0.0:8787
```

> 报 `Error: Cannot find module 'C:\Users\你的用户名\tools\tunnel.mjs'` 是因为在该目录下没有
> `tools` 文件夹（命令要用相对路径，得先在项目目录）。现在 `tunnel.mjs` 会先检查工作目录，
> 站错地方直接把正确做法打出来；嫌麻烦就用上面的 `开服.mjs`。

然后浏览器打开 `http://127.0.0.1:5350/games/party/`，在大厅里：

1. 填昵称、把「联机服务器」填成 `ws://127.0.0.1:8787/ws`（默认值就是它）。
2. 选玩法 → 设 4 位密码（可留空）→ 点「创建房间」，拿到一个 **1–5 位数字**的房间号。
3. 朋友在同一大厅里填这个房号 → 点「进入房间」。
4. 房主点「开始游戏」。

同一 WiFi 下的手机把地址换成 `ws://电脑内网IP:8787/ws` 即可（服务器同时托管静态文件，
也可以直接用手机访问 `http://电脑内网IP:8787/` 进大厅）。
部署到 Cloudflare 后前端默认连**同源 `/ws`**，不用改地址。

自测：`node server/selftest.mjs`（126 项，含 7 个玩法各跑 30 秒模拟）。

### 操作

| 按键 | 动作 |
| --- | --- |
| `A` / `←` | 向左移动 |
| `D` / `→` | 向右移动 |
| `空格`（也支持 `W` / `↑`） | 跳跃，长按跳更高 |
| `E` | ① 推进 NPC 对话 ② 打开总门选单 ③ 站在区块门前进入该内容 |
| `H` | 打开 / 关闭操作说明面板 |
| `O` 或右上角齿轮 | 打开设置面板 |
| `Esc` | 依次关闭：帮助 → 对话 / 选单 / 设置；在游戏里回大厅 |
| `↑` `↓` `←` `→` / `1`~`9` / `回车` | 总门选单里选条目、直接按序号传送 |

**走道的三条规则**：

1. 广场往左走出边缘 → 工具总门屏；往右 → 游戏总门屏；两端到头会提示「已到尽头」。
2. 在总门屏按 `E` 打开选单，选一条就**直接传送到那个区块正中**（`x=640`），面朝该区块的门。
3. 从**任何**区块走出左右边缘 → 回到中心广场；工具区落在 `x≈420`，游戏区落在 `x≈860`，
   也就是「从哪边出去的，回来还站在哪边」。

**出游戏**：游戏画面**左上角**有 `← 回上一级`、**右上角**有 `← 回大厅` 两枚按钮——
`← 回上一级` 回到进游戏前的那一屏（原位置），`← 回大厅` 回中心广场；
键盘 `Backspace` = 回上一级、`Esc` = 回大厅（点过游戏画面后焦点交给游戏，此时请用按钮）。

### 手机端触屏操作

检测到触屏设备（含 `pointer: coarse` / `maxTouchPoints>0`）才会出现虚拟按键，桌面端**完全不建 DOM、零改动**。
所有按键都是「按下去派发一次 `keydown`、抬起来派发一次 `keyup`」的合成键盘事件，复用大厅与游戏既有的键盘监听——
所以开源游戏文件一个字都不用改。

| 位置 | 屏幕按键 | 作用 |
| --- | --- | --- |
| 大厅 | 左下 `◀` `▶` | 向左移动 / 向右移动（按住 = 持续移动，抬起 = 停） |
| 大厅 | 右下 `跳` | 跳跃，长按跳更高 |
| 大厅 | 右下 `E` | 站在总门旁开选单；选单里点行即传送 |
| 通用 | 左上 `⤾` | 返回（等同 `Esc`：关面板 / 游戏里回大厅） |
| 俄罗斯方块 | `←` `→` `↻` `▼` | 方向键（`↻`=旋转、`▼`=软降） |
| 格斗 | `A` `D` `W` `S` · `J` `K` `L` `SHIFT` | 左组 A/D 移动、W 跳、S 下蹲；右组 J 拳、K 踢、L 重击、SHIFT 防御；双人对战建议电脑端 |
| 打砖块 | 左右半屏滑动 + `开球` | 手指在左 / 右半屏滑动控制挡板，点 `开球` 发球 |
| 脑力街机（贪吃蛇/小鸟/白块/飞机/泡泡龙/乒乓）+ 仓库行动 | 仅 `⤾` | 线上版自带触屏/鼠标，点屏幕直接玩；WorldHub 不派发按键，提示「本游戏支持触屏直接操作」 |
| 2048 / 五子棋 / 扫雷 / 白噪音 / 番茄钟 / 网址推荐 | 仅 `⤾` | 这些页面原生触摸已可玩，只保留返回键 |

竖屏时顶部会出现「建议横屏获得最佳体验」提示条，横屏自动消失。

> **关于 `file://` 双击直开的限制**：大厅、总门、NPC 等都在父页面里，触屏完全可用；
> 但七门游戏是 `iframe` 加载的**独立页面**，`file://` 下浏览器把 iframe 当成不透明源（cross-origin），
> 父页面无法把合成键盘事件注入其中，因此**直接在 `file://` 双击打开时，游戏内的虚拟方向键不会驱动游戏**。
> 这是浏览器同源策略的固有行为，不是代码缺陷——手机上访问**线上 `https` 站点**（或本地 `http` 静态服务器）时 iframe 同源，
> 触屏方向键、打砖块滑动、开球全部正常。桌面端用物理键盘本来就能直接玩，不受影响。

## 三、核心设计

### 3.1 场景管理器（`js/sceneManager.js`）

统一场景接口，四个方法缺一不可，切场景时**先 `destroy()` 旧场景，再 `init()` 新场景**：

```js
init(ctx, params)   // 进入场景，准备资源
update(dt)          // 推进逻辑，dt 单位为秒
render(ctx)         // 绘制，坐标系固定 1280×720
destroy()           // 离开场景，释放监听 / 定时器 / 图片
```

- **逻辑分辨率固定 1280×720**，实机像素由 `devicePixelRatio` 决定（上限 2 倍），
  CSS 只负责等比缩放，所以任何窗口尺寸下画面都不变形、不裁切。
- 主循环统一用 `requestAnimationFrame`，`dt` 钳制在 50ms 以内 ——
  切到后台再切回来时不会因为累积时间过大而一帧穿地。
- 场景接口不完整时直接抛错，避免半成品场景混进注册表。

### 3.2 12 屏世界（`js/world.js`）

世界由一张 `SCENES` 表描述，一条配置 = 一屏：

```js
{ id: 'snake', kind: 'zone', cat: 'games', title: '贪吃蛇',
  themeKey: 'right', seed: 1105, item: {...}, npcX: 800, door: { x: 960, ... } }
```

`kind` 只有三种，决定了这一屏怎么玩：

| kind | 屏 | 换屏规则 | 门 |
| --- | --- | --- | --- |
| `gate` | `gate-tools` / `gate-games` | 沿走道 `WALK` 走，两端到头锁住 | 屏幕正中一座**总门**（`isGate`，按 `E` 开选单） |
| `plaza` | `plaza` | 左右各通一座总门屏 | 无门，只有守灯人与路标 |
| `zone` | 9 个内容区块 | **任意**边缘都回广场 | 一扇门（工具 `x=320`，游戏 `x=960`） |

- `WALK = ['gate-tools', 'plaza', 'gate-games']` —— 只有这三屏是「走」过去的，
  9 个区块是「传送」过去的，所以总门屏与区块屏的换屏逻辑是两套，互不干扰。
- 传送落点 `TELEPORT_X = 640`（区块正中，面朝门）；回广场落点
  `PLAZA_LAND = { tools: 420, games: 860 }`（从哪边出去就从哪边回来）。
- 走道两端锁边用 `edgeLockL / edgeLockR`：撞边出一次「已到尽头」，往回走 60px 才解锁。

画面全部**程序化烘焙**：`mulberry32(seed)` 生成山脊、树线、路灯、星点，
一屏一张 1280×720 的离屏 canvas，进屏时烘一次、之后每帧只贴图。
同一个 `seed` 永远得到同一片景色，所以「哪个区块长什么样」是可复现的。

### 3.3 角色与手感（`js/player.js`）

- 加速度 / 摩擦 / 土狼时间（coyote time）/ 跳跃缓冲（jump buffer）四件套，
  跳起后长按还能再抬高一点，落地有明显 squash。
- `Input.reset()` 在打开浮层时清空按键状态：否则「按住 D 打开选单，关掉后角色还在跑」。
- 摄像机在走道里跟随，在区块里固定（一屏一世界，不需要滚动）。

### 3.4 总门与传送选单（`js/gatePanel.js`）

站到总门前 `near` 命中，按 `E` 调 `GatePanel.open({ cat, items, onPick })`：

- 选单是 **DOM 浮层**（不是画在 canvas 上），所以文字永远清晰、可被读屏，
  也方便用 CSS 做窄屏适配；
- 每行：序号 · 类别色点 · 名称 · 一句说明 · 「传送 →」；
- 键盘：`↑↓` / `←→` 选择，`回车` / `空格` 确认，`1`~`9` 直选，`Esc` 关闭；
  鼠标点行、点空白、点右上角 × 都能关；
- 选中即 `teleportTo(item)`：`setScene` + 角色摆到 `x=640` + 面朝门 + 一次白闪过渡。

浮层与设置面板都用 `position: fixed` 定位到**视口**而不是舞台：
舞台是 16:9 的固定框，竖屏手机上只有 190 来 px 高，跟着舞台走会把选单压成一条缝。

### 3.5 NPC 与对话（`js/npc.js` + `world.js`）

10 位 NPC，每人 4~8 句，都讲「这是什么 / 怎么玩 / 键位 / 怎么回广场」：

| 屏 | NPC | 屏 | NPC |
| --- | --- | --- | --- |
| 广场 | 守灯人 | 贪吃蛇 | 养蛇人 |
| 白噪音 | 听风者 | 2048 | 算盘先生 |

### 3.6 iframe 壳（`js/iframeScene.js`）

- 全屏 iframe 加载对应 `index.html`，**不能加 `sandbox`**（会禁掉 localStorage 与音频）；
- 两个返回入口：左上「← 回上一级」回到 `from` 场景（原位置）、右上「← 回大厅」回广场；
  键盘 `Backspace` = 回上一级、`Esc` = 回大厅；`world.js` 进 iframe 时把 `{ from, px, pf }` 传给壳，
  回上一级时 `change('world', { sceneId: from, px, pf })` 原路返回；
- 断网 / 加载失败时 iframe 的 `error` 事件触发「需要网络连接」轻量提示，返回按钮仍可用；
- `destroy()` 移除 iframe / 两个按钮 / 监听 / 离线提示并复位 `data-scene`，反复进出不留残留；
- 进游戏前 `BGM.suspend()` 把背景音乐压低到 18%，出来 `resume()` 复原。

### 3.23 加载提速批次（1.18.1）

起因：进游戏要等。测下来不是「文件太大」这么简单，而是三件事叠在一起——

1. **SW 预缓存和首次点击抢带宽**：`install` 一次并发拉 25 项（含 555KB 的脑力街机聚合页），正好撞上首屏后第一次点游戏。
   - 现在拆成 `SHELL`（首页 + 3 个产物，6 项，约 225KB）与 `LAZY`（21 个区块入口页）。
   - `install` 只拿 `SHELL`；`LAZY` 在 `activate` 后按体积升序、每 1.2 秒串行取 1 个、上限 14 项，`>256KB` 的页面自动跳过。
   - `navigator.connection.saveData` 或 `effectiveType` 为 2g 时整段跳过，不动用户流量。
   - `tools/gen-sw.mjs` 相应输出两份清单；`tools/verify-dist.mjs` 改为校验两份，并新增「SHELL 不得超过 400KB」——防止以后往 install 里塞大文件。
2. **每次进游戏都走一遍网络**：`/games`、`/tools` 原本是 network-first，即使有缓存也要先探一次。
   - 入口页与区块内静态资源改 `stale-while-revalidate`：有缓存立刻返回，后台拉新写回。整站构建会换 `VERSION` 清缓存，不会长期吃到旧资源。
   - HTTP 层 `/games/*`、`/tools/*` 补 `stale-while-revalidate=604800`，让浏览器缓存过期后也先给旧版。
3. **点了才开始下载**：15 张卡片，用户点哪张，哪张才开始请求。
   - 目录卡片加意图预热：鼠标悬停 250ms、键盘聚焦、手指按下即发一个 `priority: 'low'` 的 `fetch`。点击时同 URL 请求与它合并，不重复下载。
   - 只在明确意图时预热（不随目录打开批量预取），避免无谓流量；省流 / 2G 直接不预热。

另外两处：

- **番茄钟去掉中转**：`tools/pomodoro/index.html` 原本是 `meta refresh` 跳 `timer.html`，进一次多一个完整 RTT 加一屏白。世界条目直接指向 `timer.html`，中转页留给外部旧链接。
- **加载骨架给反馈**：过去只有一句静态「正在加载…」，8 秒才换文案。现在从第 2 秒起显示 `正在加载 · Ns`，6 秒加「网络有点慢」，15 秒加「好像卡住了」。主行定宽 + `tabular-nums`，转圈图标不会随秒数抖动；提示语单独绝对定位一行，出现与否都不改变主行宽度。
- **游戏内返回按钮**：`opacity` 从 0.55 提到 0.9、底色加深。压在游戏的浅色顶栏上原本几乎看不见。

实测（本地 + CDP 模拟限速）：

| 指标 | 优化前 | 优化后 |
| --- | --- | --- |
| SW install 预缓存 | 25 项，含 555KB 聚合页 | 6 项 / 约 225KB |
| 首屏后 5 秒内后台流量 | 约 600KB（一次性并发） | 无并发，逐个小文件 1.2s 间隔 |
| 首屏下载量 | 234KB | 222KB |
| 二次进入贪吃蛇 | 每次走网络 | 命中 SWR，直接出画面 |
| 进入番茄钟 | index.html → timer.html 两次导航 | 一次直达 |

### 3.24 拆包与联机批次（1.19.0）

这一批解决两件事：**进游戏慢**、**只能一个人玩**。

#### 一、脑力街机拆包

`games/brain-gym/index.html` 原来是 555KB 的单文件聚合页（57 个玩法 + 9 个街机函数全在里面），
从大厅点「贪吃蛇」要把整包下完才出画面。

做法是**不动上游一行代码**的前提下做物理拆分：

| 文件 | 作用 | 体积 |
| --- | --- | --- |
| `games/brain-gym/index.html` | 入口壳：认 `?game=` → HEAD 探测分片 → `location.replace` | 3.2KB |
| `games/brain-gym/brain-gym.html` | 原聚合页（首页 / 定级 / 其余玩法） | 555KB |
| `games/brain-gym/arcade/<id>.html` | 8 个街机分片，每个只带自己那个游戏 | 412–460KB |

- 分片由 `tools/gen-arcade.mjs` **生成**，不手改。脚本按字符扫描 JS（跳过字符串 / 正则 / 转义）做括号匹配，
  把「公共设施 + 该游戏的 GAMES 条目 + 菜单区 + 启动段」拼成一个自洽文档；被截掉的玩法不会留下悬空引用。
- 入口壳先 `HEAD` 探一下分片存不存在再跳，分片缺失就回退聚合页——不会掉进「壳 → 分片 → 壳」的死循环。
- 启动段加了 `BOOTED` 标志：街机直达成功就不再建首页（首页 DOM 不在分片里，建了会炸）。

实测（本地服务 + CDP 限速 1.6Mbps / RTT 80ms，清缓存冷启）：

| 路径 | 进入耗时 | 说明 |
| --- | --- | --- |
| 聚合页 `?game=tetris` | 3498ms | 555KB 全下 |
| 入口壳 → 分片 | 734ms | 只下 412KB 分片 |

8 个分片逐个实测可开局、控制台零报错（`canvas:false` 属正常：俄罗斯方块用 DOM 渲染）。

#### 二、联机模式

**房间规则**（按需求实现）：房间号 **1–5 位数字**（少于 6 位，且不允许前导 0，避免 `007` 和 `7` 撞号）；
密码可选，**4 位数字**；房主建房 → 拿房号 → 朋友输号进房 → 房主开局；2–4 人。

**架构**：服务端权威。客户端只发输入、只画快照，碰撞与胜负全在服务端算——
这样网络抖动时不会出现「我这儿撞到他了，他那儿没撞到」。

```
浏览器 ──ws──▶ 房间服务（server/index.js 本地 / functions/api/net.js Cloudflare DO）
                  │  60Hz 固定步长 step()，20Hz 下发快照
                  └─ server/room-core.js（房间表、房间号分配、断线重连、房主迁移）
                     server/games/*.js（5 个玩法，纯状态机，不碰网络）
```

| 玩法 | 操作 | 规则 | 快照体积 |
| --- | --- | --- | --- |
| 咱俩碰碰 | WASD / 摇杆 | 俯视竞技场，撞人扣血，撞墙反弹，最后活着的人赢 | ~160B/帧 |
| 泡泡堂 | 方向键 + 空格 | 15×11 格子迷宫，水泡 2.4 秒炸成十字水柱，炸木箱也炸人 | ~300B/帧 |
| 坦克大战 | ↑↓ 前后 / ←→ 转向 / 空格开炮 | 四角出生，先拿 5 分（击中 +1、击毁 +3） | ~320B/帧 |
| 贪吃蛇大作战 | ←→ 转向 | 环形地图，吃光点变长，头撞身体出局，头对头短的死 | ~730B/帧 |
| 抢答赛 | 点选项 / 1–4 | 10 道题，每题 6 秒，答对按顺序 100/80/65/55 分，答错扣 20 | ~280B/帧 |

**工程细节**：

- **断线保留 30 分钟**：连接断了不踢人，只摘连接；重连用同一个 playerId 续回原座位与分数。房主掉线自动把房主转给下一位在线玩家。
- **输入节流**：客户端 50ms 合并一次上行（输入是「当前状态」不是「事件」，丢帧不补）。
- **题干按需下发**：抢答只在换题那一帧发题干，其余帧只发状态，省一半带宽。
- **空房回收**：最后一个玩家掉线后计时，30 分钟无人则回收房间号。
- **一键起服**：`node server/index.js`，**不装任何依赖也能跑**——内置了 RFC6455 子集实现（握手 / mask 解帧 / 分片 / ping-pong / close），
  装了 `ws` 则自动优先用 `ws`。实测无依赖状态下浏览器双端建房、进房、开局、同步全部正常。
- **部署到 Cloudflare**：`functions/api/net.js` 用 Durable Object + WebSocket Hibernation 跑同一套 `room-core`，
  前端默认连**同源 `/ws`**，不用改地址。配置文件见 `wrangler.jsonc`。

**自测**：`node server/selftest.mjs` —— 80 项全绿，覆盖前后端协议逐字对比（房间号正则、错误码、消息类型）、
房间号边界（`12345` 过、`123456` 拒、`0123` 拒）、密码边界、满员拒入、非房主开局拒、掉线重连回原座位、
房主迁移、5 个玩法各跑 30 秒不发火且快照 < 6KB。

#### 五、联机上线形态（1.19.2）

Cloudflare Pages **不能**给 Functions 声明 Durable Objects —— `wrangler.jsonc` 里的
`durable_objects` / `migrations` 放 Pages 项目里会被拒。所以线上联机拆成两块：

| 块 | 部署物 | 作用 |
| --- | --- | --- |
| 静态站 | Pages 项目 `zuoye-e0c` | 页面、大厅 UI、留言板/友链 Functions |
| 房间服务 | Worker `worldhub-ws`（`wrangler.ws.jsonc`） | `/ws` 升级 + Durable Object `Rooms` |

```bash
node tools/build-ws.mjs                                   # esbuild → dist/ws-worker.js（34 KB）
npx wrangler deploy --config wrangler.ws.jsonc            # 建 DO 并发布 Worker
node tools/ws-smoke.mjs wss://worldhub-ws.<子域>.workers.dev/ws
```

前端地址解析顺序是 `?ws=` → `<meta name="wh-net">` → 同源 `/ws`，线上由
`games/party/index.html` 的 meta 指到 Worker；不带 meta 时仍会尝试同源，失败后提示手填。

`worker/entry.js` 只有 40 行：健康检查、`/api/net/games`、`/ws` 交给 DO，
其余全部复用 `functions/api/net.js` 与 `server/*`，所以**两端行为一致**——
`tools/ws-smoke.mjs`（握手、房号规则、错号拒、进房、人数、非房主开局拒、开局、快照帧率）
在本地 Node 服务与本地 wrangler dev 的 Worker 上都是 9 项全过。

### 存档

状态存于独立模块 `js/save.js`（localStorage key：`worldhub.save.v1`），不挂在场景对象上：

```js
Save.get()                        // 读整份存档（永远返回合法结构）
Save.setPlayer(x, facing, zone)   // 记录位置与区块，进门前调用
Save.allow(ids)                   // 把自建内容的屏 id 加进白名单
Save.reset()                      // 清空（调试用）
```

- 进门前写入 `{ x, facing, zone }`；回大厅 `init` 时恢复，`x` 夹在 `[40, 1240]`，
  `zone` 必须在白名单里（含 `gate-tools` / `gate-games` / 9 个区块 / 已注册的 contrib），否则回落 `plaza`；
- 第四批起**不再有「已通关 ✓」吊牌**：游戏改成 iframe 外部项目，进度由各游戏自己存
  （如 2048 的 `localStorage` 最高分、扫雷的最佳时间），大厅不参与统计；
- 所有读写都包在 `try/catch` 里：隐私模式、配额满、存档被写坏（坏 JSON / 越界坐标 / 类型不对）
  都只会回落到默认值，不会影响游戏运行。想重置进度，用设置面板的「重置存档」或清掉这几条 localStorage。

### 只在 `http(s)` 下才会暴露的坑

本地 `file://` 直开全绿，不代表线上全绿。已经踩过三个：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Failed to construct 'Worker'…origin 'null'` | `file://` 是不透明源，不能读本地 worker 脚本 | 扫雷 `initWorkers()` 加 try/catch，退回主线程等价实现 |
| `unsupported MIME type ('text/html')` | 引用了仓库里不存在的脚本，Pages 用 `index.html` 兜底（200, text/html） | 番茄钟的 `sw.js` 注册已整段移除 |
| 页面白屏但控制台无报错 | 缺图被兜底成 HTML，`<img>` 静默失败 | 逐页查 `document.images` 的 `naturalWidth === 0` |

另外 Pages 对**大小写敏感**：`Images/x.png` 在 Windows 上能读到，线上 404。改资源路径后务必在线上再点一遍。

### 1.24.7 · 不用下载也能开隧道

`cloudflared` 要下 53 MB，网不好的时候能卡在 0% 半天——而它只是用来「把本机端口暴露到公网」
这一件事。这件事 Windows 自带的 ssh 也能做。

新版优先级改成：

```
node 开服.mjs
  ├─ 系统有 ssh？ → ssh -R 连 localhost.run，零下载，几秒出地址
  └─ 没有/失败   → 才去下 cloudflared
```

`--no-ssh` 可以跳过第一条直接用 cloudflared。

**踩到的一个隐蔽 bug**：localhost.run 连上后先刷几千字符的 ANSI 欢迎横幅，
真正的地址（`https://xxxx.app.lhr.life`）夹在横幅后面。第一次实现里为了省内存
只保留输出尾部，结果地址跟着横幅一起被丢掉，`match` 永远匹配不到 → 误判成「ssh 不行」。
改法是**全程累积、绝不截断**，并且连续剥两遍 ANSI（横幅是嵌套序列，剥一遍不够）。

```js
buf += String(b);
const clean = buf.replace(/\x1b\[[0-9;?]*[a-zA-Z]/g, '').replace(/\x1b\[[0-9;?]*[a-zA-Z]/g, '');
const m = clean.match(/https:\/\/[a-z0-9-]+\.(?:app\.lhr\.life|lhr\.life)/i);
```

另外两处：`-tt` 不能加（加了地址会被塞进伪终端 UI，解析不出来）；
下载器从「只显示百分比」改成「每 1.5 秒报已下载 MB」，卡住 12 秒无数据直接换源。

**这条路的边界**：localhost.run 只做纯 HTTP 转发，不带 WebSocket 升级。
所以 ssh 隧道只能让你「打开页面」，房间连接要用本机的 `ws://<内网IP>:端口/ws`。
要「一个链接全搞定」（页面+联机都走同一条隧道），还是得 cloudflared。

实测：

| 项目 | 结果 |
| --- | --- |
| 零下载路径 | 3 次均成功出地址 |
| 隧道 `/healthz` | 200 |
| 隧道根路径 | 200 + 说明页，正确显示两条地址（局域网 / 当前地址） |
| 完整工程 `node server/index.js` | 行为不变 |

### 1.24.9 · 断线不再白玩一局，手机端补上真正的适配

联机能玩了之后，真正会让人摔手机的是这两类问题：**掉一次线这局就废**，和**手机上根本看不清**。

#### ① 断线重连：只重试 1 次就躺平

实测（杀服务端进程，再启回来等 22 秒）：客户端 `_retry` 停在 1，状态一直是 `offline`，
房间号还在但永远连不回去。指数退避写了 5 档，实际只能走 1 档。

根因在 `js/party/net.js` 两处：

1. `onopen` 里有一句 `self._retry = 0`。服务端刚关时会出现「握手成功 → 立刻被关」的抖动，
   这句等于把计数反复归零，退避形同虚设。改成**连接稳定 3 秒后才清零**。
2. `_tryNext()` 走到「候选地址全失败」时**只发一个 `ALLFAILED` 事件就 return**。
   服务端被杀时 TCP 是「拒绝」不是「超时」，握手永远不成功，于是每次重连都走这个分支，
   而它不安排下一次重试 —— 重连链就断在这一帧。

现在统一走 `_scheduleReconnect()`：0.8s → 1.6 → 3.2 → 6.4 → 8s，最多 60 次（≈8 分钟）。
并且用 `_everOnline` 区分「连上过又断了」和「从来没连上」——后者不重试，直接报给 UI，
免得用户对着一个永远不会好的转圈等。

#### ② 续房没带 token：自己变成旁观者

重连时 `_rejoin()` 只发了 `{ code, pass, name }`。服务端 `JOIN` 分支从不认旧身份，
每次都 `pid = 'u' + 新号`，于是重连后 `you` 从 `u9iwyh` 变成 `ucfshx`：
原来的座位、分数、游戏内的坦克全留在原地，自己成了第四个人。

修法是两头一起改：

- 客户端 `_rejoin()` 带上 `pid` + `token`；
- 服务端 `JOIN` 核对 `player(pid).token`，对得上就 `pid = back.id` 复用原 id（4 人满房也不再拦）。

#### ③ 重连后按键失灵：两个渲染循环抢一个 net

这条最隐蔽。现象是重连后按住 S，`S.axis.y` 明明是 1，服务端收到的全是 `thr: 0`，坦克一动不动。

链路是这样的：续房时服务端补发 `JOINED`（`resumed: true`）和 `START`（`rejoin: true`）→
大厅的 `joined` / `start` 处理器无条件 `render()` → `app.innerHTML = ''` 把舞台拆了重建 →
**旧舞台的 rAF 循环不会自己停**，和新循环一起往 `net.input` 塞数据，后写的 `thr: 0` 覆盖真实输入。

三处一起改：

- 续房的 `JOINED` / `START` 不重建舞台（舞台本来就活着，后续快照会让它自己追上）；
- `frame()` 开头加 `document.documentElement.contains(wrap)` 闸，宿主脱离文档立即停；
- `PartyKit.open()` 开头先调上一次的 `_teardown()`，避免监听器叠加。

#### ④ 掉线不再立刻判死

`Room.detach()` 里原本 `if (this.state === 'playing') p.alive = false` ——
WiFi 抖一下、手机切个后台就等于被淘汰。改成记 `droppedAt`，在 `_loop` 里按 **15 秒宽限**检查，
超时才判死并通知游戏模块；重连回来则清掉标记、`alive` 翻回 true。

同时补了「全员掉线时循环被停过，重连要重新 `startLoop()`」—— 否则单人掉线后再回来，
对局是永久冻结的。

#### ⑤ 服务端重启后房间没了，不能装死

房间是内存态，服务端一重启必然丢。这时 `net.room` 还留着旧对象，`render()` 会照着它继续画舞台，
玩家盯着一块永远不动的画面以为在重连。

现在收到 `NO_ROOM` / `CLOSED` 且本地还有房间时：清房、回大厅、提示

## 1.24.2 · 联机开局界面修复

修掉一个藏得比较深的联机缺陷：**房主点「开始游戏」后，双方都停在房间页，看不到对局画面。**

原因在 `js/party/lobby.js` 的 `net.on('room')` 分支：它用 `app.querySelector('.pk-wrap')` 判断
「是否已经在对局舞台」，而对局舞台真正的根节点是 `renderGame()` 里创建的 `.pp-stage`

改法：判断改成 `.pk-wrap, .pp-stage` 两个都认，并补注释写明这层结构差异，避免以后又被改回去。

## 1.24.1 · 修复线上联机连不上

**问题**：线上联机大厅一直显示「未连接」，建房进不去。

**根因**：Cloudflare Pages 项目**不能**给 Functions 绑 Durable Object（官方限制，`durable_object_bindings` 字段 PATCH 会被静默忽略），所以 `zuoye-e0c.pages.dev/ws` 根本不存在，请求直接 404。联机真正跑在独立 Worker（`worldhub-ws`）上，但前端仍按同源 `/ws` 去连——地址收敛时把 UI 上的地址去掉了，却没留部署层注入点。

**改法**（三处，都不把地址暴露给界面）：

| 改动 | 位置 | 说明 |
| --- | --- | --- |
| 候选地址 + 故障转移 | `js/party/net.js` | 解析顺序 `?ws=` → `meta wh-net`（支持空格/逗号分隔多个）→ 同源 `/ws`；逐个尝试，握手超时 4 秒自动换下一个，全部失败才报 `ALLFAILED` |
| 坏地址记忆 | `js/party/net.js` | 确认不通的地址在重连时排到最后，用户不用每点一次「重试」就再干等一轮；不清除，换网络后仍会重试 |
| 打包注入 | `tools/make-deploy.mjs` | 线上包的 party 页 meta 写入 Worker 地址；源码保持空值走同源。可用 `WH_NET_ENDPOINTS` 覆盖 |

**失败文案**也分了情况：`ALLFAILED` 提示「当前网络可能限制了联机域名，可换网络/开热点/重试」，中途断线则提示自动重连中。

专项验收 `tools/e2e-net-fallback.mjs` **17/17 全绿**（地址解析顺序与去重、坏地址在前自动换到可用地址、全部不通报 ALLFAILED、逗号分隔写法、坏地址记忆、握手与心跳）。块⑥联机回归 40/40、球场 e2e 30/30 全绿。

**几个值得记的点**

- **加载终态是单向的**：iframe 一旦判了 `timeout/error/notfound`，迟到的 `load` 事件不能翻回 `loaded`——浏览器加载 404 页也会触发 `load`，不拦就会「失败提示一闪变成功」。只能由用户点「重试」重新进入 `loading`。同源门连 `fetch HEAD` 都失败也进 `error` 态（导航失败时浏览器常触发 `load` 而非 `error`）。
- **弹窗不能假同步**：`WHModal.confirm/prompt` 返回 Promise，所有调用点必须 `async/await`；`alert` 不取返回值，可在同源 iframe 安全覆盖并桥接到父窗。
- **键盘适配的暗坑**：输入框若在模块安装监听前就 autofocus，聚焦列表为空、上推不触发——安装末尾补查 `document.activeElement`。
- **格斗键位真相**：`mk.js` 里 P1 是 `WASD + J/K/L + Shift`，P2 是方向键 + `P/[/\` + Ctrl；页面旧提示写的是上一版键位，触屏派发也在误控 P2，已一并对齐。
- **预置网址自检**：`node tools/check-links.mjs` 覆盖格式、伪协议、黑名单 24 词、URL 归一化去重、注入字符、锁定项、条数；154 条全过，`ming-games` 保持锁定。

**全量回归**：`server/selftest.mjs` 127 项、`tools/predict-lag.mjs`、`tools/verify-dist.mjs` 28 项、`tools/e2e-pitch.mjs` 30/30、块①~⑦专项（30/35/40/29/40/51）全绿。详见 `第八批-交付报告.md`。

### 1.21.0 · 客户端预测 + 球场 2v2（第 7 个联机玩法）

上一版补的是「内容深度」，这一版补的是**联机手感**，并加了第 7 个玩法。

**A. 客户端预测**（碰碰 / 坦克 / 球场 三个连续移动玩法）

服务端权威 + 快照回放 = 按键到画面差一个来回。跨境 150ms 下这一下就是「按下要等、松手还滑」。
现在每帧先在本地用**和服务端同一份物理函数**把自己往前推一步，快照到达后再摆回权威状态、
把未确认的输入逐帧重放，剩下的差值按比例抹平。

| 链路 | 坦克 不预测 → 开预测 | 碰碰 | 球场 |
| --- | --- | --- | --- |
| 跨省 80ms | 100ms → 0ms | 150ms → 17ms | 117ms → 17ms |
| **跨境 150ms** | **217ms → 0ms** | **250ms → 17ms** | **183ms → 33ms** |
| 跨境 250ms | 200ms → 0ms | 250ms → 17ms | 383ms → 17ms |
| 抖动+丢包 | 283ms → 0ms | 283ms → 17ms | 217ms → 17ms |

视觉误差均值 1~8px、**硬贴合 0 次**（硬贴合 = 误差太大直接瞬移，看到「拉扯」就是它）。

三条硬约定：**同源物理**（`tools/gen-physics.mjs` 从 `server/games/*.js` 的 `#shared-begin…end` 原样抽出
`js/party/shared.js`，带 `__hash`，自测比对，改物理忘生成直接报错）、**ack 回显**（输入带 `seq`，
快照带 `ak: [[pid, seq]]`）、**绝对量不重放**（朝向/血量不进历史，否则「转了多少」会累加两遍）。

> 注意「跟手」和「位置误差」是两件事：`tools/predict-lag.mjs` 测前者（按下后第几帧画面开始动），
> `tools/predict-sim.mjs` 测后者（延迟画面 vs 真值，天然等于 RTT×速度）。用后者判跟手会得出荒谬结论。

**B. 球场 2v2**（新玩法）

2v2 带球射门，先进 3 球或 3 分钟到点；草地 / 冰面两种手感；身体撞球推走、空格抽射（球在脚边 70px，冷却 0.42s）。
人和球是同一套确定性物理，所以**连球都能本地预测**：自己用预测出的位置+速度推球，别人只用插值位置推球
（不知道他的速度也不猜），重放历史时球换成插值快照（否则拿「未来的球」重放「过去的自己」）。

球感调了两轮：`PUSH` 从 1.12（球比人快）改成 **0.9**（球比人慢一点）。原因是球摩擦比人摩擦小，
按人的全速给球加速会一脚把球送到 400+，而人最多 360——3 秒只有 19/180 帧碰到球，其余时间都在追。
改完接触帧 **19 → 131/180**，球稳贴在脚前 54px。

**顺手修掉的三个线上真问题**

| 问题 | 根因 | 现象 |
| --- | --- | --- |
| 房间广播失效 | `server/index.js` 的 `attach()` 返回 `{pid, emit}`，而 `Room.broadcast` 调 `p.conn.send(...)`，异常被 `try/catch` 吞掉 | 双人进房后**互相看不见** |
| 预测崩溃 | `games.js` 里贪吃蛇的「场地高 `SH`」覆盖了模块级的「共享物理 `SH`」 | 先进过贪吃蛇再进球场：`SH.stepPlayer is not a function` |
| 球卡死角 | 球速每帧「先乘摩擦、再被墙反号」，人一直往里压时球速长期 ±14 px/s | 球被顶进角落后**卡一整局**（30 秒 0 进球） |

**自测**：`node server/selftest.mjs` —— **128 项全部通过**（新增 7.5 球场物理 7 项、8 预测内核 7 项、9 跟手仿真 5 项）；
`node tools/e2e-pitch.mjs` —— 真 Chromium 开两页进同一房间，**30 项**（按下即动、端到端进球、两端比分一致、无 JS 异常）。
详见 `1.21.0-客户端预测与球场-交付报告.md`。

> **构建日期的坑**：`tools/build.mjs` 原来用 `new Date().toISOString().slice(0,10)` 取日期，
> 那是 **UTC** 日期，中国晚上 8 点后构建会写成「昨天」。已改成按本地时区拼 `YYYY-MM-DD`。
> 只是版号显示问题，不影响缓存指纹（指纹来自内容 hash）。
